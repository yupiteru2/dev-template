# 標準開発テンプレート

Claude Codeでの開発を「後付け・手戻り」に陥らせないためのガードレール一式。
**要件の確定 → 設計 → 実装** の順を、忘れようがない場所に固定して配る。

## なぜ「貼るプロンプト」ではなくテンプレートなのか

失敗は**バグ報告を受けた瞬間**に起きる。その瞬間に自動で読み込まれる場所
（`CLAUDE.md`・スキル）にルールが無ければ効かない。手で貼る方式は、貼るのを
忘れた時＝急いでいる時にこそ効かない。

実例: あるプロジェクトでは、継ぎ足し修正の原因が**`bugfix`スキルに
「最小修正。周辺の気になる箇所は触らず報告のみ」と書いてあったこと**だった。
不具合報告のたびに自動で読まれるので、手順どおりに継ぎ足しが起きていた。
ガードレール自体が原因側にあった、という構図。

## 中身

```
global/                     → ~/.claude/ へ配る（全プロジェクトに効く）
  CLAUDE.md                 開発共通ルール。要件の確定・問題対応の作法
  skills/requirement-driven/ 要件駆動フロー（フェーズ0〜4）
  要件駆動プロンプト.md       Claude Code以外で使う保険
project/
  CLAUDE.md.template        新規プロジェクト用のひな型
適用.ps1                     配布・回収スクリプト
```

## 使い方

### 全プロジェクトへ適用（初回・更新時）

```powershell
cd C:\Claude\dev-template
.\適用.ps1 -Global
```

`~/.claude/` の既存ファイルは `~/.claude/_backup_<日時>/` へ退避してから上書きする。

### 新規プロジェクトを始めるとき

```powershell
.\適用.ps1 -Project C:\Claude\新プロジェクト
```

`CLAUDE.md`（ひな型）と `.claude/skills/` を用意する。**ひな型は穴埋め式**なので、
最初のセッションで実際の内容に置き換えること。

### 運用中に `~/.claude/` を直接直したものを取り込む

```powershell
.\適用.ps1 -Collect
```

`~/.claude/` の内容を `global/` へ戻す。差分を確認してからコミットする。

## 3層構造

| 層 | 場所 | 効き方 |
|---|---|---|
| 1 常時ガードレール | `~/.claude/CLAUDE.md` | 全プロジェクト・全セッションで自動読込。最強 |
| 2 手順書 | `~/.claude/skills/requirement-driven/` | 必要時に読み込み。1の肥大を防ぐ |
| 3 携帯用プロンプト | `要件駆動プロンプト.md` | 自動化できない環境向けの保険 |

## 同名スキルの優先順位に注意

プロジェクト側に同名スキル（例: `requirement-driven`）を置くと、**そのプロジェクト内では
プロジェクト側が優先されグローバルが読まれない**。プロジェクト固有の内容を足したい場合は、
プロジェクト側の冒頭に「グローバルを先に読むこと」という導線を必ず張る。

## 注意: `.ps1` は BOM付きUTF-8 で保存する

Windows PowerShell 5.1 は `.ps1` を既定でANSIとして読むため、**BOMが無いと日本語が
壊れて構文解析に失敗する**（`適用.ps1` は BOM付きで保存済み）。編集ツールによっては
BOMが落ちるので、日本語を含む変更をしたら先頭バイトを確認すること。

```powershell
[System.IO.File]::ReadAllBytes('.\適用.ps1')[0..2]   # 239 187 191 (EF BB BF) ならOK
```

## リモート

個人情報を含みうるため**Webリモート（GitHub等）へはpushしない**。
バックアップはローカルまたは家庭NASのbareリポジトリへ。

```powershell
git clone --bare C:\Claude\dev-template \\NAS\backup\dev-template.git
git remote add nas \\NAS\backup\dev-template.git
```
